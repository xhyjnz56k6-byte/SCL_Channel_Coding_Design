# S6 译码算法对比项目记录

## 1. 项目名称

**S6：BCH、卷积码与 LDPC 译码算法对比及结果汇总**

---

## 2. 实验目的

本阶段在已有 BCH、卷积码和 LDPC 工程基础上，对不同译码方案的性能与工程代价进行统一整理和补充验证。

主要目标如下：

1. 对比 BCH 分组查表译码与整块 BM+Chien 译码的性能、纠错能力、复杂度、存储量和译码时延。
2. 对比卷积码整块与时隙组织下的硬判决、浮点软判决 Viterbi 译码。
3. 分析时隙滑窗译码的 CPU 计算时间、首输出时延、比特决策时延和存储开销。
4. 对比 Direct BG2 N560 LDPC 的 BP 与 NMS 译码性能、迭代次数、复杂度和译码时延。
5. 统一生成中文科研结果图，并正确处理高信噪比下 BER、FER 为零的绘图问题。

老师文档规定：高速卷积码可根据时隙内承载长度进行分块，采用连续编码与滑窗 Viterbi 译码，以支持连续处理和提前输出；整块和时隙方式均支持硬判决与软判决。

---

## 3. 总体实验条件

### 3.1 信道与调制

* 调制方式：BPSK
* 信道：AWGN
* 信噪比横轴：符号信噪比
* 正式扫描范围：-5 dB 至 10 dB
* 扫描间隔：0.5 dB
* 总信噪比点数：31

BPSK 映射为：

$$
x =
\begin{cases}
+1, & b=0 \
-1, & b=1
\end{cases}
$$

符号信噪比线性值为：

$$
\gamma_s = 10^{\frac{E_s/N_0\text{(dB)}}{10}}
$$

AWGN 噪声方差为：

$$
\sigma^2 = \frac{1}{2\gamma_s}
$$

实际码率统一定义为：

$$
R = \frac{K_{\mathrm{payload}}}{N_{\mathrm{tx}}}
$$

符号信噪比与比特信噪比的换算关系为：

$$
\frac{E_b}{N_0}\text{(dB)}
= \frac{E_s}{N_0}\text{(dB)}
10\log_{10}R
$$

### 3.2 停止条件

每个信噪比点采用以下停止规则：

* 最小仿真帧数：1000
* 目标错误帧数：200
* 最大仿真帧数：50000

停止条件为：

$$
N_{\mathrm{frames}}\geq1000
\quad\text{且}\quad
N_{\mathrm{frameErrors}}\geq200
$$

若未达到目标错误帧数，则运行到：

$$
N_{\mathrm{frames}}=50000
$$

# 4. BCH 实验

## 4.1 实验目的

对比两种 BCH 工程方案：

1. 200 bit 分组 BCH：BCH-S200，使用 syndrome 查表译码。
2. 200 bit 整块 BCH：BCH-B200，使用 BM+Chien 代数译码。

需要说明：

> 两种方案的码型、码率、组织方式和纠错能力不同，因此 BER、FER 差异不能全部归因于查表译码与 BM 译码本身。

---

## 4.2 实验参数

| 参数     |     BCH-S200 |        BCH-B200 |
| ------ | -----------: | --------------: |
| 原始信息长度 |      200 bit |         200 bit |
| 编码组织   |           分组 |            整块缩短 |
| 码型     | BCH(15,11,1) | 缩短 BCH(255,207) |
| 分组数量   |           19 |               1 |
| 编码后长度  |      285 bit |         248 bit |
| 实际码率   |     0.701754 |        0.806452 |
| 理论纠错能力 |    每组纠正1 bit |     整块纠正最多6 bit |
| 译码方法   |  syndrome 查表 |        BM+Chien |
| 信道     |    BPSK+AWGN |       BPSK+AWGN |

码率分别为：

$$
R_{\mathrm{S200}}
=
\frac{200}{285}
\approx0.701754
$$

$$
R_{\mathrm{B200}}
=
\frac{200}{248}
\approx0.806452
$$

---

## 4.3 实验方法

### BCH-S200

处理流程：

```text
200 bit payload
→ 填充并划分为19个11 bit子块
→ 每个子块采用BCH(15,11,1)编码
→ 拼接为285 bit码字
→ BPSK
→ AWGN
→ 硬判决
→ 逐子块计算syndrome
→ syndrome查表
→ 单比特纠正
→ 恢复200 bit payload
```

单个子块的理论纠错能力为：

$$
t=1
$$

整帧成功条件不是“总错误数不超过19”，而是每个子块都满足：

$$
w_i\leq1
$$

其中，$$w_i$$ 表示第 $$i$$ 个 BCH 子块内的错误数量。

### BCH-B200

处理流程：

```text
200 bit payload
→ 缩短BCH(255,207)编码
→ 得到248 bit发送码字
→ BPSK
→ AWGN
→ 硬判决
→ 计算12个syndrome
→ Berlekamp-Massey求错误位置多项式
→ Chien搜索错误位置
→ 翻转错误位
→ post-syndrome校验
→ 恢复200 bit payload
```

理论纠错能力为：

$$
t=6
$$

即在整个缩短码字内满足：

$$
w\leq6
$$

时应保证正确恢复。

1. 新增分组 BCH 操作级计数器。
2. 新增 BM、Chien 和有限域操作计数器。
3. 新增分类内存统计。

7. 正式执行完整 31 点 AWGN 网格。
8. 对旧版本内存峰值统计进行修复。

10. 对所有结果生成配置哈希、环境哈希和文件哈希。

## 4.7 BCH 主要结果

| 方案       | 信噪比点数 |  总仿真帧数 |  加权平均译码时间 |     最大观测时间 |     译码器内存 |
| -------- | ----: | -----: | --------: | ---------: | --------: |
| BCH-S200 |    31 | 448965 | 10.217 μs | 25240.3 μs | 1580 byte |
| BCH-B200 |    31 | 605049 | 17.415 μs | 27491.4 μs | 2408 byte |

主要结论：

1. B200 具有整块 $$t=6$$ 的纠错能力，可靠性优于局部单错分组保护。
2. S200 查表译码平均 CPU 时间较低。
3. B200 需要 syndrome、BM、Chien 和有限域运算，因此计算与存储开销更高。
4. 最大时延受 Windows 调度、CPU 变频和后台任务影响，只作为当前平台观测值。
5. 两种 BCH 方案不能只根据译码器名称进行纯算法归因。

# 5. 卷积码实验

## 5.1 实验目的

卷积码实验分为两组：

1. 整块编码条件下比较硬判决与浮点软判决 Viterbi。
2. 时隙连续编码条件下比较硬判决与浮点软判决滑窗 Viterbi。

同时区分：

* CPU 译码时间
* 首输出时延
* 平均决策时延
* P95 决策时延
* 整帧恢复时延

---

## 5.2 基础参数

| 参数      | 设置          |
| ------- | ----------- |
| payload | 300 bit     |
| 约束长度    | $$K=7$$     |
| 生成多项式   | 171/133 八进制 |
| 母码率     | 1/2         |
| 尾比特     | 6           |
| 编码后长度   | 612 bit     |
| 实际码率    | 0.490196    |
| 信道      | BPSK+AWGN   |
| 硬判决度量   | 汉明距离        |
| 软判决度量   | 浮点可靠度度量     |

实际码率为：

$$
R_{\mathrm{CC}}
=\frac{300}{2(300+6)}

\frac{300}{612}
\approx0.490196
$$

---

## 5.3 实验组一：整块 Hard/Soft

| 项目   | 整块硬判决          | 整块浮点软判决        |
| ---- | -------------- | -------------- |
| 组织方式 | Block          | Block          |
| 判决输入 | 1 bit          | Float          |
| 回溯方式 | Full traceback | Full traceback |
| 回溯深度 | 306            | 306            |
| 窗口长度 | 306            | 306            |
| 滑动步长 | 300            | 300            |

实验流程：

```text
300 bit payload
→ 添加6个尾比特
→ R1/2卷积编码
→ 612 bit BPSK
→ AWGN
├─ 硬判决 → Hard Viterbi
└─ 浮点软信息 → Float Soft Viterbi
→ 完整回溯
→ 恢复300 bit payload
```

该实验主要回答：

* 软信息带来多少 BER、FER 改善；
* 浮点软判决增加多少分支度量计算；
* 硬判决是否能显著降低 CPU 时间。

---

## 5.4 实验组二：时隙 Hard/Soft

时隙组织包括：

| 方案           | 时隙划分        |
| ------------ | ----------- |
| B_CONT_50x6  | 50 bit × 6  |
| C_CONT_100x3 | 100 bit × 3 |
| D_CONT_150x2 | 150 bit × 2 |

统一滑窗参数：

| 参数         |  数值 |
| ---------- | --: |
| 回溯深度 $$D$$ |  70 |
| 窗口长度 $$W$$ | 128 |
| 滑动步长 $$S$$ |  25 |
| 窗口触发次数     | 约9次 |

实验流程：

```text
300 bit payload
→ 按时隙划分
→ 编码器状态连续
→ R1/2连续卷积编码
→ BPSK+AWGN
├─ 硬判决序列
└─ 浮点软信息序列
→ 滑窗Viterbi
→ 达到回溯深度后提前输出稳定比特
→ 恢复完整payload
```

---

## 5.5 时隙方案的复杂度原因

相邻窗口重叠长度为：

$$
W-S=128-25=103
$$

每次窗口前移25个符号，但会重复处理103个历史符号。

整块每帧 ACS 约为：

$$
N_{\mathrm{ACS,block}}
= 306\times64\times2

39168
$$

当前时隙实现每帧 ACS 约为：

$$
N_{\mathrm{ACS,slot}}
\approx143998
$$

两者比例为：

$$
\frac{N_{\mathrm{ACS,slot}}}
{N_{\mathrm{ACS,block}}}
\approx
\frac{143998}{39168}
\approx3.68
$$

因此，时隙方案 CPU 时间较长的主要原因是：

> 当前实现对重叠窗口中的 trellis 区域进行重复计算。

这不代表时隙方案不适合实时传输。

---

## 5.6 实时性指标解释

整块方案需要等待完整码字后输出。

时隙滑窗方案可以：

* 边接收
* 边更新路径度量
* 边回溯
* 提前输出已经稳定的比特

当前结果中：

| 指标        |         整块方案 |         时隙方案 |
| --------- | -----------: | -----------: |
| 首输出时延     | 约610 symbols | 约298 symbols |
| 平均决策时延    | 约311 symbols | 约231 symbols |
| 译码器内存     |   59776 byte |   26112 byte |
| CPU平均译码时间 |           较低 |           较高 |

首输出时延减少量约为：

$$
610-298=312\text{ symbols}
$$

相对降低约为：

$$
\frac{312}{610}\times100%
\approx51.1%
$$

因此，时隙方案的实时性主要体现在：

1. 首输出更早。
2. 平均比特决策等待时间更短。
3. 可以连续流水处理。
4. 所需缓存更小。
5. 可以适配固定业务时隙。

实时性并不等价于整帧 CPU 总时间最短。

---

## 5.7 卷积码优化内容

1. 整块与时隙结果统一接入 S6。
2. 将 Hard/Soft 和 Block/Slot 作为两个独立维度。
3. 时隙 Hard/Soft 使用相同的 $$D=70$$、$$W=128$$、$$S=25$$。
4. CPU 时间与决策时延分开统计。
5. 增加 ACS、回溯、窗口触发和内存字段。
6. 明确 Hard 输入为1 bit，Float Soft 为浮点软信息。
7. 对高信噪比 BER、FER 为零的点不绘制人工水平线。
8. 统一中文标题、坐标和图例。

当前仍可进一步优化：

```text
保存上一窗口末尾路径度量
→ 每次只计算新增的S=25个trellis步
→ 使用环形survivor buffer
→ 避免重复计算W-S=103个历史符号
```

---

## 5.8 卷积码主要结果

| 方案                      | 加权平均 CPU 译码时间 |      最大观测时间 |         内存 |
| ----------------------- | ------------: | ----------: | ---------: |
| BLOCK_FLOAT_SOFT        |    523.997 μs |  65607.2 μs | 59776 byte |
| BLOCK_HARD              |    339.026 μs |  34231.5 μs | 59776 byte |
| B_CONT_50x6_FLOAT_SOFT  |   1849.688 μs | 163059.1 μs | 26112 byte |
| B_CONT_50x6_HARD        |   1565.576 μs |  67275.4 μs | 26112 byte |
| C_CONT_100x3_FLOAT_SOFT |   1838.859 μs | 137930.3 μs | 26112 byte |
| C_CONT_100x3_HARD       |   1550.952 μs |  36739.9 μs | 26112 byte |
| D_CONT_150x2_FLOAT_SOFT |   1835.824 μs |  87817.1 μs | 26112 byte |
| D_CONT_150x2_HARD       |   1549.167 μs |  64246.2 μs | 26112 byte |

主要结论：

1. 浮点软判决 BER、FER 优于硬判决，但 CPU 时间更高。
2. 时隙滑窗方案的总 CPU 时间高于整块方案。
3. 时隙方案 CPU 时间增加主要来自重叠窗口重复计算。
4. 时隙方案首输出时延和平均决策时延低于整块方案。
5. 时隙方案使用更少的译码缓存。
6. 当前时隙实现属于功能正确但计算冗余较高的参考实现。
7. 历史 CC 结果不是严格 pair-stop，因此应作为已有正式结果整合，而不是重新声明为全新配对实验。

# 6. LDPC 实验

固定 Direct BG2 N560，比较 BP 与 NMS 译码在以下方面的差异：

* BER
* FER
* 平均迭代次数
* 最大迭代比例
* 提前停止比例
* 操作复杂度
* 译码存储
* 平均与最大译码时延

---

| 参数        |            数值 |
| --------- | ------------: |
| payload   |       300 bit |
| 编码后长度     |       560 bit |
| 实际码率      |      0.535714 |
| 基图        |           BG2 |
| 提升因子      |            56 |
| filler    |           148 |

R_{\mathrm{LDPC}}

## 6.5 优化内容

1. 固定使用 N560，避免不同码长干扰。
2. BP/NMS 共用同一 LLR 和相同校验矩阵。
3. 使用 syndrome 提前停止。
4. NMS 归一化因子固定为0.95。
5. 分开统计 BP 非线性运算与 NMS 最小值运算。
6. 输出 correct-valid、wrong-valid、correct-invalid、wrong-invalid。
7. 统一整合平均、中位、P95和最大时延。
8. 不将“代码支持10、20、30次”错误表述为已完成正式实验。

## 6.6 LDPC 主要结果

| 方案       | 信噪比点数 |  总仿真帧数 |   加权平均译码时间 |     最大观测时间 |         内存 |
| -------- | ----: | -----: | ---------: | ---------: | ---------: |
| N560 BP  |    31 | 460561 | 140.687 μs | 34024.9 μs | 11312 byte |
| N560 NMS |    31 | 460561 |  33.157 μs |  9468.0 μs | 11312 byte |

主要结论：

1. BP 作为性能基准。
2. NMS 去除了 BP 中大量 tanh 和 atanh 运算。
3. NMS 平均 CPU 时间明显低于 BP。
4. NMS 可能存在一定 BER、FER 性能损失。
5. 当前正式结果最大迭代次数为32。
6. 10、20、30次最大迭代尚未形成正式性能曲线。

# 7. 科研绘图方法

## 7.1 绘图规则

所有结果图：

1. 从原始 CSV 逐点读取。
2. 不修改原始实验数据。
3. 不平滑。
4. 不插值。
5. 不重新生成数据点。
6. BER、FER 使用对数纵轴。
7. CPU 时间使用线性纵轴。
8. 图题、横轴、纵轴和图例使用简洁中文。
9. 每张图同时输出：

   * PNG
   * figure-data CSV
   * plot manifest
   * plot check
   * 中文 readme.txt

---

## 7.2 高信噪比零值处理

原始 BER、FER 为零时：

$$
BER_{\mathrm{raw}}=0
$$

或：

$$
FER_{\mathrm{raw}}=0
$$

原始 CSV 保持为0，但对数坐标图不绘制该点。

figure-data 中记录：

```text
rawValue = 0
plotValue = 空值
isPlotted = false
isZero = true
```

零误帧时可保存近似95%上界：

$$
FER_{95%,\mathrm{upper}}
\approx
\frac{3}{N_{\mathrm{frames}}}
$$

该上界只用于审计，不绘制人工水平线。

# 10. 结果总结

| 编码类型  | 性能优先方案             | 低复杂度方案       | 主要结论                        |
| ----- | ------------------ | ------------ | --------------------------- |
| BCH   | B200整块BM+Chien     | S200分组查表     | B200纠错能力更强，S200实现和平均时延更低    |
| 卷积码   | Float Soft Viterbi | Hard Viterbi | 软判决性能更好，硬判决CPU开销更低          |
| 卷积码组织 | 时隙滑窗适合提前输出         | 整块CPU总时间较低   | 时隙方案用更多计算换取更低首输出与决策时延       |
| LDPC  | BP                 | NMS          | BP作为性能基准，NMS显著降低非线性计算与CPU时间 |

# 11. 已知问题

1. BCH-S200 与 B200 不是同一码型下的纯译码器替换实验。
2. BCH 内存统计不包含 STL 分配器全部隐藏开销。
3. CC 历史正式结果不是严格 pair-stop。
4. 当前时隙滑窗实现重复计算重叠 trellis，CPU 开销较高。
5. 时隙 CPU 总时间高不代表实时性差，应结合首输出和决策时延分析。
6. LDPC 10、20、30次最大迭代没有正式性能结果。
7. 不同模块的时延来自不同历史实验环境，不能直接进行跨模块绝对排名。
8. 最大译码时延受 Windows 调度和后台任务影响。
9. 当前 GitHub 交付提交与部分实验内部记录的源码提交号不同，应区分实验提交与交付提交。
