# S7 交织抗突发错误实验项目记录

## 1. 项目名称

**S7——BCH码与卷积码在连续突发信道下的交织性能分析**

---

## 2. 实验目的

本实验研究交织对连续突发错误的分散作用，重点回答以下问题：

1. 不同交织方法能否降低 BCH 码和卷积码在突发信道下的 BER、FER；
2. 突发长度和突发位置如何影响译码结果；
3. 交织深度或交织跨度如何影响抗突发性能；
4. 交织带来的 CPU 处理开销和结构缓冲量是多少；
5. 在性能、缓冲量和实现复杂度之间，哪种交织方案更适合作为推荐方案。

LDPC 只保留无交织 AWGN 历史参考，不参与本次交织收益排名。

---

## 3. 统一信道模型

### 3.1 BPSK 调制

编码比特采用 BPSK 调制：

$$
x_k=
\begin{cases}
+1, & b_k=0,\\
-1, & b_k=1.
\end{cases}
$$

### 3.2 连续突发极性反转信道

信道在连续区间内对 BPSK 符号执行极性反转，并叠加 AWGN：

$$
y_k=h_kx_k+n_k
$$

其中：

$$
h_k=
\begin{cases}
-1, & s\le k<s+L,\\
+1, & \text{其他位置},
\end{cases}
$$

$$
n_k\sim\mathcal{N}(0,\sigma^2)
$$

噪声方差为：

$$
\sigma^2=
\frac{1}
{2\times 10^{E_s/N_0\text{(dB)}/10}}
$$

突发长度按照编码后长度计算：

$$
L=\operatorname{round}\left(\rho N_{\mathrm{tx}}\right)
$$

其中，$\rho$ 为突发比例，$N_{\mathrm{tx}}$ 为编码后发送长度。

本实验采用的突发比例为：

$$
\rho\in\{2\%,5\%,10\%\}
$$

突发不绕回，接收机不知道突发发生的位置。

---

# 5. BCH 实验

## 5.1 BCH 编码与译码参数

| 参数 | 设置 |
|---|---|
| 原始输入长度 | 200 bit |
| 基本子码 | BCH$(15,11,1)$ |
| 子块数量 | 19 |
| 编码后长度 | 285 bit |
| 理论输入容量 | $19\times11=209$ bit |
| 实际 payload | 200 bit |
| 判决方式 | BPSK 硬判决 |
| 译码方式 | syndrome 查表译码 |
| 单个子块纠错能力 | 1 bit |

实际码率为：

$$
R_{\mathrm{BCH}}
=
\frac{200}{285}
\approx0.7018
$$

BCH 整帧由19个 BCH 子块构成。只要任意子块中的错误数超过1 bit，该子块就可能误纠或译码失败。

---

## 5.2 BCH 交织配置

| 配置 | 参数 | 交织范围 | 缓冲量 |
|---|---:|---:|---:|
| 无交织 | NONE | 1 bit | 0 bit |
| BCH码块交织 | $D=19$ | 285 bit | 285 bit |
| 行列交织 | rows=15 | 285 bit | 285 bit |
| 全帧伪随机交织 | span=285 bit | 285 bit | 285 bit |

### BCH码块交织

19个 BCH 子块按行排列，每行15 bit，按列发送：

$$
19\times15=285\ \text{bit}
$$

该方法能够将连续发送错误分散到不同 BCH 子块。

### 行列交织

将285 bit构造成：

$$
15\times19
$$

的交织矩阵，按一种顺序写入、另一种顺序读出。

### 全帧伪随机交织

对整帧285 bit执行固定种子的伪随机置换。该方法能够随机分散错误，但不能保证每个 BCH 子块最多只得到1个错误。

---

## 5.4 BCH 实验方法

BCH 单帧链路为：

```text
随机生成200 bit payload
→ 19×BCH(15,11,1)编码
→ 交织
→ BPSK调制
→ 连续极性反转
→ AWGN
→ 硬判决
→ 解交织
→ syndrome查表译码
→ 恢复200 bit payload
→ 统计BER、FER及误纠情况
```

BER 定义为：

$$
\mathrm{BER}
=
\frac{N_{\mathrm{bit,error}}}
{N_{\mathrm{frame}}\times200}
$$

FER 定义为：

$$
\mathrm{FER}
=
\frac{N_{\mathrm{frame,error}}}
{N_{\mathrm{frame}}}
$$

其中，只要一帧中存在至少1个错误信息 bit，该帧就计为错误帧。

---

## 5.5 BCH 实现与优化

1. BCH syndrome 查找表在 runner 初始化时只构造一次，后续所有帧复用；
2. 所有交织映射均生成正置换和逆置换，并检查：

   * 索引不越界；
   * 无重复索引；
   * 无缺失索引；
   * 交织和解交织逐 bit 恢复；
3. 四种 BCH 配置在同一比较组共享 payload、噪声和突发起点；
4. C++ 与 MATLAB smoke 对照完成逐 bit 和最终结果检查；
5. 正式绘图不对 BER、FER 数据进行平滑；
6. 高 SNR 下原始零值不替换为伪小值，不绘制水平 error floor；
7. 10%全起点热力图因全部方案 FER 饱和，退出正式图清单，仅保留2%和5%全起点热力图。

---

## 5.6 BCH 主要结果

### 不同突发比例的结论

| 突发比例 | 结果                                                 |
| ---: | -------------------------------------------------- |
|   2% | 码块交织和行列交织在高 SNR 下可将 FER 降至约 $10^{-4}$～$10^{-3}$ 量级 |
|   5% | 码块交织和行列交织仍有明显收益；全帧伪随机与无交织在帧级指标上接近失效                |
|  10% | 所有配置 FER 接近或等于1，当前 BCH-S200 无法承受                   |

10%突发包含29个强错误，而系统只有19个 BCH 子块。即使最理想地分散，也至少存在一个子块得到两个错误：

$$
\left\lceil\frac{29}{19}\right\rceil=2
$$

由于每个 BCH 子块只能纠正1 bit，因此10%突发超过了该方案的结构纠错上限。

### 推荐结果

当前综合推荐：

**行列交织 rows=15**

其主要原因是：

1. 2%和5%突发下性能稳定；
2. 与码块交织性能接近；
3. 全帧缓冲量为285 bit；
4. 结构清晰，便于实现和解释。

在10 dB、六位置最坏 FER 不超过0.1的判据下，支持已测试的5%突发，但不支持10%突发。

---

## 5.7 BCH 误纠限制

BCH$(15,11,1)$ 是单错误纠正码。连续突发导致某个子块出现多个错误时，syndrome 查表可能把多错误模式错误映射为单错误模式，产生误纠。

正式实验累计记录：

| 指标        |         数值 |
| --------- | ---------: |
| 未检出错误帧    |  5,439,787 |
| 误纠 BCH 子块 | 23,251,548 |

因此最终报告必须明确：

> BCH 的部分帧错误不是显式译码失败，而是译码器输出了错误但合法的码字。

## 5.8 BCH 时间与缓冲结果

| 配置           |        纯译码时间 |       交织CPU时间 |      解交织CPU时间 |     缓冲量 |
| ------------ | -----------: | ------------: | ------------: | ------: |
| 无交织          | 约8.55 $\mu$s | 约0.333 $\mu$s | 约0.315 $\mu$s |   0 bit |
| BCH码块交织 D=19 | 约9.16 $\mu$s | 约0.329 $\mu$s | 约0.332 $\mu$s | 285 bit |
| 行列交织 rows=15 | 约9.05 $\mu$s | 约0.328 $\mu$s | 约0.327 $\mu$s | 285 bit |
| 全帧伪随机交织      | 约8.93 $\mu$s | 约0.327 $\mu$s | 约0.335 $\mu$s | 285 bit |

纯译码时间定义为：

$$
T_{\mathrm{decode}}
=t_{\mathrm{decoder,end}}

t_{\mathrm{decoder,start}}
$$

该时间不包含解交织、硬判决、信道、文件写入和绘图。

交织处理总时间为：

$$
T_{\mathrm{interleaving}}
=
T_{\mathrm{interleave}}
+
T_{\mathrm{deinterleave}}
$$

当前工程没有定义编码后 bit rate，因此285 bit缓冲量不能直接换算成微秒。若以后定义发送速率为 $R_b$，则结构等待时间可写为：

$$
T_{\mathrm{buffer}}
=
\frac{285}{R_b}
$$

# 6. 卷积码实验

## 6.1 卷积码参数

| 参数          | 设置              |
| ----------- | --------------- |
| payload     | 300 bit         |
| 约束长度        | $K=7$           |
| 生成多项式       | 171/133（八进制）    |
| 母码率         | $1/2$           |
| 尾比特         | 6               |
| trellis 时刻数 | 306             |
| 编码后长度       | 612 bit         |
| 调制          | BPSK            |
| 判决          | 浮点软判决           |
| 译码          | 终止卷积码软判 Viterbi |

实际码率为：

$$
R_{\mathrm{CC}}
=
\frac{300}{612}
\approx0.4902
$$

卷积码编码后，每个 trellis 时刻产生两个母码输出：

$$
\left[c_{t,0},c_{t,1}\right]
$$

交织时始终把这两个输出作为一个整体移动，不允许拆开。

---

## 6.2 卷积码交织配置

| 配置      |       参数 |              窗口跨度 |     缓冲量 | 角色     |
| ------- | -------: | ----------------: | ------: | ------ |
| 无交织     |     NONE |    1 trellis step |   0 bit | 基线     |
| 短深度块交织  |    $D=8$ |  64 trellis steps | 128 bit | 推荐工程配置 |
| 短深度块交织  |   $D=16$ | 128 trellis steps | 256 bit | 等跨度控制组 |
| 局部伪随机交织 | span=128 | 128 trellis steps | 256 bit | 推荐工程配置 |

短深度块交织窗口为：

$$
W=8D
$$

因此：

$$
W_{D=8}=64\ \text{trellis steps}
$$

$$
W_{D=16}=128\ \text{trellis steps}
$$

D=8与伪随机128的跨度不同，不能解释为纯交织方法差异。

真正的等跨度受控比较为：

$$
\text{D=16短深度块交织}
\quad\text{vs.}\quad
\text{伪随机交织 span=128}
$$

## 6.4 卷积码实验方法

单帧链路为：

```text
随机生成300 bit payload
→ 卷积编码并添加6个尾比特
→ 按trellis时刻成组交织
→ BPSK调制
→ 连续极性反转
→ AWGN
→ 计算LLR
→ 解交织LLR
→ 浮点软判Viterbi译码
→ 恢复300 bit payload
→ 统计BER和FER
```

接收 LLR 为：

$$
L_k
===

\frac{2y_k}{\sigma^2}
$$

由于接收机不知道突发位置，在反转区间仍按普通 AWGN 信道计算 LLR。因此，高 SNR 下突发区间会产生绝对值很大、方向错误的 LLR。

---

## 6.5 卷积码实现与优化

1. 交织单位固定为 trellis step；
2. 同一 trellis 时刻的两个母码输出始终保持相邻；
3. 交织和解交织映射逐项验证互逆；
4. 接收端先生成 LLR，再对 LLR 解交织，最后进入软判 Viterbi；
5. 禁止在解交织前进行硬判决；
6. D=8、D=16和伪随机128分别记录 span、buffer 和比较角色；
7. Formal 同组共享 payload、AWGN、突发起点和停止帧集合；
8. 图01实际固定5%突发并对六种位置取均值；
9. 对FER接近1的结果不进行平滑，只允许调整绘图范围和线型；
10. 六位置完全重合时通过图注、线型或子图说明，不人为修改数据。

---

## 6.6 卷积码主要结果

### 2%突发

在10 dB附近，FER大致为：

| 配置             |   FER |
| -------------- | ----: |
| 无交织            | 约1.00 |
| 伪随机交织 span=128 | 约0.44 |
| 短深度块交织 D=8     | 约0.54 |
| 短深度块交织 D=16    | 约0.72 |

2%突发下，伪随机 span=128 的 FER 最低，但仍未达到预设突发容限：

$$
\mathrm{FER}_{\mathrm{worst}}>0.1
$$

因此不能认为卷积码已经可靠承受2%连续强反转突发。

### 5%突发

在10 dB附近，六位置平均 FER 大致为：

| 配置             |     FER |
| -------------- | ------: |
| 无交织            |  1.0000 |
| 短深度块交织 D=8     |  1.0000 |
| 伪随机交织 span=128 | 约0.9997 |
| 短深度块交织 D=16    | 约0.9945 |

5%突发下四种配置均接近完全失效。D=16虽然在 FER 上比 D=8略低，但该差异只有约：

$$
1-0.9945=0.0055
$$

即0.55个百分点，不能被解释为明显可靠性提升。

### 10%突发

所有配置的 FER 基本等于1，说明当前卷积码和交织配置不能承受10%连续极性反转。

## 6.7 BER与FER差异

卷积码中可能出现 BER 已下降而 FER 仍接近1的情况。

若每个300 bit帧平均有5个错误 bit，则：

$$
\mathrm{BER}
=
\frac{5}{300}
\approx0.0167
$$

但只要每帧都至少有1个错误：

$$
\mathrm{FER}=1
$$

5%突发、10 dB附近的数据为：

| 配置     |     BER | 平均每帧错误bit |     FER |
| ------ | ------: | --------: | ------: |
| 无交织    | 约0.0169 |      约5.1 |  1.0000 |
| D=8    | 约0.0891 |     约26.7 |  1.0000 |
| 伪随机128 | 约0.0694 |     约20.8 | 约0.9997 |
| D=16   | 约0.1300 |     约39.0 | 约0.9945 |

平均每帧错误 bit 估计为：

$$
N_{\mathrm{bit,error/frame}}
=
300\times\mathrm{BER}
$$

该结果表明：

> D=16虽然偶尔多恢复了少量完整帧，但失败帧中的错误扩散更加严重，因此BER反而最高。

---

## 6.8 D=8与D=16的结果解释

2%突发约包含12个编码 bit，即约6个母码输出对。D=8的64-step窗口已经能够完成有效分散，继续扩大到128-step可能产生更多分离的 Viterbi 错误事件。

5%突发约包含31个编码 bit，即约15～16个母码输出对。D=16的128-step窗口可将错误分散到更长 trellis 范围，因此极少数帧能够完全恢复，FER略低。

但该现象不是单调关系：

$$
\text{交织深度增加}
\not\Rightarrow
\text{BER和FER同时改善}
$$

交织深度需要与突发长度和 Viterbi 错误事件结构共同匹配。

---

## 6.9 卷积码位置敏感性

在5%突发、伪随机 span=128下：

* 帧首 FER 基本为1；
* 四分之一 FER 基本为1；
* 帧中 FER 基本为1；
* 四分之三 FER 基本为1；
* 帧尾 FER 基本为1；
* 随机位置在高 SNR 下约为0.998～0.999。

五个固定位置曲线完全重合：

$$
\mathrm{FER}_{\mathrm{HEAD}}
=
\mathrm{FER}_{\mathrm{QUARTER}}

\mathrm{FER}_{\mathrm{MIDDLE}}

\mathrm{FER}_{\mathrm{3/4}}

\mathrm{FER}_{\mathrm{TAIL}}
=1
$$

随机位置由于每帧改变起点，偶尔出现更有利的窗口边界关系，因此能够多恢复极少数帧。

---

## 6.10 卷积码时间和缓冲结果

| 配置           |       纯译码时间 |      交织CPU时间 |     解交织CPU时间 |     缓冲量 |
| ------------ | ----------: | -----------: | -----------: | ------: |
| 无交织          | 约309 $\mu$s | 约0.75 $\mu$s | 约0.40 $\mu$s |   0 bit |
| 伪随机 span=128 | 约307 $\mu$s | 约0.75 $\mu$s | 约0.40 $\mu$s | 256 bit |
| D=16         | 约307 $\mu$s | 约0.79 $\mu$s | 约0.43 $\mu$s | 256 bit |
| D=8          | 约308 $\mu$s | 约0.74 $\mu$s | 约0.39 $\mu$s | 128 bit |

结果说明：

1. 四种配置使用相同软判 Viterbi，因此纯译码时间基本处于同一量级；
2. 交织和解交织 CPU 时间远小于 Viterbi 译码时间；
3. D=8只需128 bit缓冲，而D=16和伪随机128需要256 bit缓冲；
4. 当前没有定义传输 bit rate，因此缓冲量不转换为微秒。

# 10. 综合结论

1. BCH 的结构化交织效果明显优于无交织和全帧伪随机交织；
2. BCH推荐行列交织 rows=15，可支持已测5%突发，但不能支持10%突发；
3. BCH伪随机交织不能保证每个 BCH 子块最多1个错误，因此在5%突发下容易发生子块碰撞；
4. 卷积码在连续强极性反转模型下整体性能较差，即使2%突发的最坏 FER 仍未达到0.1；
5. 卷积码推荐工程配置为伪随机 span=128，但该推荐是相对比较，不代表已经满足可靠通信要求；
6. D=8与D=16不存在单调优劣关系，交织窗口必须与突发长度和 Viterbi 错误事件结构匹配；
7. FER和BER必须同时分析，FER略低并不一定表示错误bit总量更少；
8. 交织CPU处理时间较小，实际主要代价是结构缓冲量；
9. 本工程未定义 bit rate、符号率或采样率，因此缓冲等待只能用 bit 或 trellis step表示，不能直接换算为物理时间；
10. 当前实验完成了代码验证、C++/MATLAB一致性检查、正式仿真、全起点扫描、时延统计、科研绘图和最终审计。
