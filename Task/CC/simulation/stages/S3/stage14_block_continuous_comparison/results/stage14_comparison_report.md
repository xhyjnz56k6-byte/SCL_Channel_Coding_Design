# Stage14 整块/连续滑窗比较报告

整块方案一次收完整帧后利用已知零终止回溯，边界定义最清晰、性能最好，但首 bit 只能在整帧译码结束后交付。连续方案保持编码器和 puncture phase，中间 slot 不重置；相对于每 slot 独立终止，50×6、100×3、150×2 分别避免 30、12、6 个重复 tail input bits。本次 300 bit 有限实验仍在最后统一加 6 个尾 bit，所以 A-D 的实际 transmitted length 相同。

滑窗 window96/slide25/Dtb70 在 warmup 后可批量提前输出，代价是 traceback 深度与批次调度带来的决定延迟，并可能产生相对完整块的性能差异。三种连续 slot 组织共享完全相同的编码比特和译码输出，差别只在业务边界归属；50 bit slot 边界更密集，边界统计样本更多。

当前软件结果推荐：可靠性优先或离线帧处理使用 A；实时高速电文使用 C（100×3）作为边界频率与调度粒度的折中。B 的更新粒度更细但业务边界更密，D 边界少但 slot 交付粒度更粗。R23 滑窗差异沿用 Stage13 的真实记录，未隐藏。
