# BCH S2 多信道正式实验详细规划

## 1. 实验总目标

本次实验面向低速 200 bit 和 300 bit 电文，比较不同 BCH 组织方式在以下五类信道条件下的性能：

1. AWGN 信道；
2. 固定多径信道；
3. 残余载波频偏信道；
4. 短时遮挡信道；
5. 连续突发错误信道。

其中，交织只在连续突发错误场景下进行对比，不在 AWGN、多径、频偏和短时遮挡场景中启用。

最终需要分别针对 200 bit 和 300 bit 电文回答：

* 哪一种 BCH 方案 BER 最低；
* 哪一种 BCH 方案 FER 最低；
* 哪一种方案实际码率最高；
* 哪一种方案译码时延最低；
* 哪一种方案误纠率最低；
* 哪一种方案在特定信道下综合最优；
* 是否存在所有信道条件下都占优的方案；
* 分块方案和整块方案分别适合什么场景。

# 3. 正式实验 Case 矩阵

## 3.1 输入长度

固定研究：

```text
K_payload = 200 bit
K_payload = 300 bit
```

每一帧的 payload 均独立随机生成。

## 3.2 四种编码方案

每一种输入长度均比较以下四类方案：

### 方案一：BCH(15,11,1) 分块方案

建议 Case 前缀：

```text
S15
```

特点：

* 每个子块包含 11 bit 信息；
* 编码后为 15 bit；
* 每个子块纠正 1 bit 错误；
* 使用 syndrome 查表译码；
* 多个子块独立译码；
* 任一 payload bit 恢复错误，则整帧 FER 计错。

### 方案二：基于 BCH(255,207) 的适配方案

建议 Case 前缀：

```text
M255K207
```

对于 200 bit：

* 使用单块缩短 BCH；
* 在母码 207 个信息位置中补 7 个已知 0；
* 编码后删除这 7 个缩短位置；
* 实际发送长度：

[
N=255-7=248
]

* 实际码率：

[
R=\frac{200}{248}\approx0.80645
]

对于 300 bit：

* 一个 BCH(255,207) 无法装入 300 bit；
* 必须采用合法多码块组帧；
* 建议优先采用尽量均衡的两块 payload 分配，例如：

[
150+150
]

* 每一块分别缩短编码；
* 需要在 `stage02_case_contract` 中根据复杂度、长度和公平性最终冻结；
* 不能将 300 bit 强行作为一个 207 信息位母码的输入。

### 方案三：基于 BCH(511,421) 的适配方案

建议 Case 前缀：

```text
M511K421
```

200 bit 和 300 bit 均可使用单块缩短方式。

对于 payload 长度 (K)，缩短量为：

[
s=421-K
]

实际发送长度为：

[
N=511-s=K+(511-421)=K+90
]

因此：

200 bit：

[
N=290,\qquad R=\frac{200}{290}\approx0.68966
]

300 bit：

[
N=390,\qquad R=\frac{300}{390}\approx0.76923
]

### 方案四：基于 BCH(511,385) 的适配方案

建议 Case 前缀：

```text
M511K385
```

200 bit 和 300 bit 均可使用单块缩短。

对于 payload 长度 (K)：

[
s=385-K
]

实际发送长度：

[
N=511-s=K+(511-385)=K+126
]

因此：

200 bit：

[
N=326,\qquad R=\frac{200}{326}\approx0.61350
]

300 bit：

[
N=426,\qquad R=\frac{300}{426}\approx0.70423
]

# 4. 统一通信仿真链路

除连续 bit 突发错误模型外，主要物理链路统一为：

```text
随机 payload
→ BCH组帧与编码
→ BPSK调制
→ 信道干扰
→ 接收机统一前处理
→ 硬判决
→ BCH译码
→ 去除缩短位/填充位
→ 多码块重组
→ payload恢复
→ BER/FER及状态统计
```

BPSK 映射统一为：

[
x=
\begin{cases}
+1,&b=0\
-1,&b=1
\end{cases}
]

码率统一使用：

[
R=\frac{K_{\text{payload}}}{N_{\text{encoded}}}
]

其中 `N_encoded` 必须是该帧实际发送的编码比特总数。

AWGN 噪声方差统一为：

[
\sigma^2=
\frac{1}
{2R\cdot10^{E_b/N_0/10}}
]

每一帧必须重新生成独立随机噪声，不能将同一个高斯噪声向量重复用于不同帧。

# 9. stage04_error_capability：理论纠错能力验证

目录：

```text
Task/BCH/simulation/stages/S2/stage04_error_capability/
```

## 9.1 阶段目标

验证每个 BCH 母码的理论纠错能力在实际缩短和组帧实现中保持正确，并审计超出纠错能力后的行为。

## 9.2 注错类型

对每个独立码块注入：

* 0 bit 错误；
* 1 bit 错误；
* (2,\ldots,t) bit 错误；
* (t+1) bit 错误；
* (t+2) bit 错误；
* 随机位置错误；
* 相邻连续错误；
* 码字首部错误；
* 码字尾部错误；
* 系统位错误；
* 校验位错误。

分块方案额外测试：

* 两个错误落入同一个 BCH(15,11) 子块；
* 两个错误跨越相邻子块；
* 错误落在分块边界两侧；
* 多个子块各有 1 个错误；
* 只有 filler 对应位置受到影响。

多块 BCH(255,207) 方案额外测试：

* 错误全部落在第一码块；
* 错误全部落在第二码块；
* 错误均匀分布；
* 一个码块成功、另一个码块失败。

## 9.3 状态分类

每一帧至少分类为：

```text
TRUE_SUCCESS
DETECTED_FAILURE
MISCORRECTION
UNDETECTED_ERROR
PAYLOAD_ERROR
```

定义：

* `TRUE_SUCCESS`：payload 与发送前完全相同；
* `DETECTED_FAILURE`：译码器明确报告失败；
* `MISCORRECTION`：译码器声称成功，但输出了错误码字或错误 payload；
* `UNDETECTED_ERROR`：译码后 syndrome 或状态未报告失败，但 payload 错误；
* `PAYLOAD_ERROR`：最终 payload 存在至少 1 bit 错误。

## 9.4 Gate

```text
PASS_STAGE04_ERROR_CAPABILITY
```

必须满足：

* 所有保证纠错范围内的合法错误图样均正确恢复；
* BCH(15,11) 单错查表结果正确；
* 缩短位映射无错误；

# 14. stage09_cfo_validation：残余 CFO 模型验证

目录：

```text
Task/BCH/simulation/stages/S2/stage09_cfo_validation/
```

## 14.1 模型定义

正式 CFO 模型必须将初始相位与累计频偏分开：

[
\phi[k]=\phi_0+k\Delta\phi
]

接收信号可表示为：

[
y[k]=x[k]e^{j\phi[k]}+n[k]
]

主实验固定：

[
\phi_0=0
]

仅研究残余累计相位变化。

## 14.2 BPSK 接收处理

由于 CFO 后信号为复数，必须冻结接收机处理方式，例如：

```text
取实部后硬判决
```

或者：

```text
经过统一的残余相位补偿后再硬判决
```

所有 BCH 方案必须使用相同处理方式。

## 14.3 验证点

* (\Delta\phi=0,\phi_0=0) 时与 AWGN 完全一致；
* 仅设置 (\phi_0) 时，所有符号相位相同；
* 设置 (\Delta\phi) 时，相位随符号索引线性累积；
* C++ 和 MATLAB 的弧度/角度单位一致；
* 正负频偏结果在对称接收机条件下合理；
* 不允许把每符号相位误差误写成整帧总相位。

# 18. stage13_burst_validation：连续突发错误与交织验证

目录：

```text
Task/BCH/simulation/stages/S2/stage13_burst_validation/
```

## 18.1 模型定义

在译码前对连续编码 bit 进行翻转：

[
r_i'=
\begin{cases}
1-r_i,&s\leq i<s+L\
r_i,&\text{其他}
\end{cases}
]

该模型属于编码比特级连续错误模型，不等同于完整物理波形突发干扰。

最终报告中必须明确这一点。

## 18.2 交织位置

交织链路：

```text
BCH编码
→ 交织
→ 突发错误
→ 解交织
→ BCH译码
```

非交织链路：

```text
BCH编码
→ 突发错误
→ BCH译码
```

交织不能放在译码之后，也不能漏掉接收端解交织。

## 18.3 交织器要求

至少冻结一种确定性交织器：

```text
固定伪随机排列
```

排列由以下信息确定：

```text
caseId
encodedLength
interleaverSeed
```

必须保证：

* 排列是完整双射；
* 无重复索引；
* 无遗漏索引；
* 解交织为严格逆排列；
* checkpoint/resume 后排列不变；
* 不同 encoded length 不误用同一维度排列。

可以增加行列交织作为扩展，但不能在主实验中同时更换太多变量。

## 18.4 验证场景

* (L=0)；
* (L=1)；
* (L=t)；
* (L=t+1)；
* 突发完全位于一个子块；
* 突发跨越两个子块；
* 突发落在分块边界；
* 突发位于码字开头；
* 突发位于码字末尾；
* 随机起点；
* 有交织；
* 无交织。

# 24. 正式停止规则

每个正式参数点采用三重限制：

```text
minFrames
minFrameErrors
maxFrames
```

停止逻辑：

1. 未达到 `minFrames` 时不得停止；
2. 达到 `minFrames` 后，若达到 `minFrameErrors` 可以停止；
3. 若始终达不到目标错误帧数，则运行到 `maxFrames`；
4. 记录明确的 `stopReason`；
5. FER 为 0 时保留原始结果，不添加伪错误；
6. 绘图时采用明确的零值显示策略。

推荐的零 FER 绘图策略：

[
FER_{\text{plot}}=\frac{0.5}{N_{\text{frames}}}
]

该值只用于 log 轴显示，原始 CSV 中 FER 仍然保存为 0，并增加字段：

```text
isZeroObserved = true
plotSurrogateUsed = true
```

# 29. 本次实验最终应形成的结论类型

最终报告不能只写：

```text
某某 BCH 性能最好。
```

而应分别形成以下结论。

## 29.1 AWGN 场景

说明：

* 整块联合纠错是否优于大量短块；
* 更低码率的母码是否换来明显 FER 收益；
* BCH(511,385) 的额外冗余是否值得；
* 200 bit 和 300 bit 是否具有不同最优方案。

## 29.2 多径场景

说明：

* 统一 MMSE 后不同 BCH 的剩余差异；
* 编码性能和均衡器性能的边界；
* 相对 AWGN 的 SNR 损失；
* 长码是否更易受多径边界影响。

## 29.3 CFO 场景

说明：

* 码长增加是否导致累计相位误差更严重；
* 高纠错能力能否抵消较长暴露时间；
* 哪种方案对残余 CFO 最稳健；
* 初始相位和累计频偏是否表现不同。

## 29.4 短时遮挡场景

说明：

* 集中错误对分块和整块结构的不同影响；
* 遮挡位置是否影响 BCH(15,11)；
* 绝对遮挡长度和遮挡比例的区别；
* 可容忍长度只能作为阈值或下界表述。

## 29.5 突发错误场景

说明：

* 分块边界效应；
* 整块 BCH 的理论保证区；
* 交织如何改变错误分布；
* 交织不会增加 BCH 总纠错能力；
* 长突发时交织收益为什么减弱；
* 哪种方案最适合搭配交织。

## 29.6 工程推荐

分别给出：

```text
可靠性优先方案
码率优先方案
低时延优先方案
低复杂度优先方案
突发错误场景推荐方案
综合折中方案
```

不能预设 BCH(15,11) 一定是最终最优，也不能因为某个整块 BCH 的 AWGN 曲线最好，就宣布其在全部复杂信道中都最优。
