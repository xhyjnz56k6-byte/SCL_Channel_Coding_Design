## 2. \(E_s/N_0\) 不是“比特信噪比”

你写的是：

> 横轴统一使用比特信噪比：\(E_s/N_0\)

这个说法在概念上矛盾：

- \(E_s/N_0\)：符号能量信噪比；
- \(E_b/N_0\)：信息比特能量信噪比。

因此正式图应写成：

```text
横轴：Es/N0（dB）
中文名称：符号信噪比
```

不能写：

```text
比特信噪比 Es/N0
```

既然你在卷积码 S3 和 LDPC S4 中均已冻结使用 \(E_s/N_0\)，S5 最好继续使用它，避免重新运行基线。卷积码 S3 已采用：

\[
\sigma^2=\frac{1}{2\cdot10^{(E_s/N_0)_{\mathrm{dB}}/10}}
\]

并冻结了 \(-5\sim10\) dB、步长 0.5 dB 的正式网格。fileciteturn0file3

同时建议 CSV 保留：

```text
esN0Db
ebN0Db
actualRate
sigmaSquared
```

转换关系应统一为：

\[
\left(\frac{E_b}{N_0}\right)_{\mathrm{dB}}
=
\left(\frac{E_s}{N_0}\right)_{\mathrm{dB}}
-10\log_{10}R
\]

其中：

\[
R=\frac{K_{\mathrm{payload}}}{N_{\mathrm{tx}}}
\]

这样正式图用 \(E_s/N_0\)，后续仍可审计并生成 \(E_b/N_0\) 对比图。

## 3. 频偏、多普勒和多径不能继续只用实数 BPSK 链路

目前 S3、S4 的链路本质是：

```text
bit
→ 实数BPSK：+1/-1
→ 实数AWGN
→ 实数LLR
```

这种链路可以模拟 AWGN，也可以模拟简单的实数 FIR 多径，但**无法正确表示载波频偏引起的相位旋转**。

S5 必须升级为复基带：

\[
x_k\in\{+1+j0,-1+j0\}
\]

频偏模型：

\[
r_k=x_k
e^{j(2\pi\varepsilon k+\phi_0)}
+n_k
\]

多径模型：

\[
r_k=\sum_{\ell=0}^{L-1}h_\ell x_{k-d_\ell}+n_k
\]

否则把“频偏”写成实数幅度变化，不是正确的 CFO 模型。

因此必须新增且隔离：

```cpp
applyAwgn(...)
applyMultipath(...)
applyCarrierFrequencyOffset(...)
applyDoppler(...)
applyShortBlockage(...)
applyBurstInterference(...)
equalizeMultipath(...)
compensateFrequencyOffset(...)
computeComplexBpskLlr(...)
```

每一个函数只能完成一个明确操作，不得把“多径 + AWGN + 均衡 + LLR”全部揉成一个函数。

## 4. “不出现 error floor”不能理解成删除真实结果

你以前要求去掉的，是高 SNR 零错误点被人为替换为 \(10^{-5}\) 后形成的伪水平线。这个要求完全正确：

- CSV 中真实零值保留为 0；
- 对数图中零值不绘制；
- 不把 0 替换为 \(10^{-5}\)、\(10^{-6}\)；
- 不连接零错误点；
- 不添加“error floor”水平标记。

但是在 S5 中，多径未完全均衡、残余频偏、多普勒、遮挡和突发干扰都可能产生**真实的高 SNR 性能平台**。这种真实平台不能删除，否则就改变了原始实验结论。

因此第⑨条建议改成：

> 禁止人为制造、替换或标注 error floor。零错误点不得用固定小正数代替。若原始数据在高信噪比下因残余多径、频偏、多普勒、遮挡或突发干扰形成真实平台，必须保留原始数据，并在报告中解释其物理原因，不得删除真实数据点。

# 三、建议的 S5 总体研究逻辑

S5 最终不是简单回答“谁的 FER 更低”，而应回答：

```text
在相近发送长度和相同300 bit净荷下，
卷积码与LDPC面对不同类型信道损伤时，
谁更可靠、谁时延更低、谁对同步误差更敏感，
以及不同场景下应该采用哪一个方案。
```

正式链路建议统一为：

```text
公共300 bit payload
→ CC或LDPC编码
→ BPSK复基带映射
→ 指定信道损伤模块
→ AWGN
→ 接收端补偿或均衡
→ 硬判决/软信息生成
→ Viterbi或NMS译码
→ 恢复300 bit payload
→ BER/FER/时延/鲁棒性统计
```

注意：

- 多径、频偏和多普勒必须说明接收机是否补偿；
- 短时遮挡和突发错误必须说明发生位置、长度和强度；
- 同一公平组共享 payload、信道状态、噪声和帧范围；
- 不同编码长度不能强行逐符号一一对应，但应共享相同随机状态生成规则。

# 四、六类信道的具体边界

## 1. AWGN

作用：

- 作为 S5 回归基线；
- 检查新复基带链路是否复现 S3、S4 的 AWGN 结果；
- 验证重构信道框架没有改变旧结论。

必须先做：

```text
旧实数AWGN
vs
新复基带AWGN
```

在同一 payload、标准噪声和 SNR 下，BER、FER 应一致或在浮点容差范围内一致。

---

## 2. 多径

建议使用符号级整数时延 FIR，不要在当前阶段引入分数时延和采样率。

模型：

\[
y[k]=\sum_{\ell=0}^{L-1}h_\ell x[k-d_\ell]
\]

必须冻结：

```text
路径数量
整数符号时延
各路径复增益
总功率是否归一化
每帧固定还是随机
是否加入AWGN
均衡器类型
接收端是否知道真实信道
卷积尾部如何截取
```

推荐第一轮使用：

```text
固定3径
整数符号时延
每帧相同信道
已知真实信道
线性MMSE均衡
```

这样可以先隔离编译码性能，不把信道估计误差混进来。

建议模块：

```cpp
normalizePathPowers(...)
applyMultipathLinearConvolution(...)
buildConvolutionMatrix(...)
mmseEqualize(...)
trimConvolutionTail(...)
```

多径 formal 不应同时改变路径数、时延、功率和均衡器。先冻结一个代表性信道。

---

## 3. 频偏 CFO

模型：

\[
y[k]=x[k]e^{j(2\pi\varepsilon k+\phi_0)}+n[k]
\]

必须冻结：

```text
normalizedCfo
initialPhaseRad
frameLengthReference
是否进行频偏补偿
补偿使用真实CFO还是估计CFO
是否保留残余频偏
```

我建议不要直接测试“完全不补偿的很大 CFO”。那样所有编码都会迅速失效，得到的是同步失败结论，而不是编码方案差异。

正式设置应采用：

```text
理想补偿后的残余CFO
```

也就是研究接收机完成粗同步后剩余的误差。

---

## 4. 多普勒

必须明确：多普勒不是简单换一个名字的固定频偏。

可以分为：

```text
固定多普勒：
整帧近似恒定频移，实质接近CFO

时变多普勒：
相位增量或衰落系数随符号变化
```

S5 建议研究时变模型，例如：

\[
y[k]=h[k]x[k]+n[k]
\]

其中 \(h[k]\) 随时间变化。

但是第一轮不要直接上复杂 Jakes 多径瑞利模型。建议先做：

```text
单径、幅度固定、相位随时间非线性变化
```

以区分：

- 固定 CFO；
- 时变 Doppler。

需要记录：

```text
normalizedDoppler
phaseTrajectory
coherenceLengthSymbols
frameIndex
channelStateHash
```

---

## 5. 短时遮挡

模型可设为：

\[
y[k]=a[k]x[k]+n[k]
\]

遮挡区间：

\[
a[k]=10^{-A_{\mathrm{block}}/20}
\]

非遮挡区间：

\[
a[k]=1
\]

必须冻结：

```text
遮挡长度
遮挡衰减dB
每帧遮挡次数
起点固定还是随机
是否允许跨越编码边界
遮挡发生在加噪前还是后
```

建议使用：

```text
每帧最多一次
起点由固定seed随机生成
按整帧比例定义持续长度
衰减而非直接置零
```

因为 CC 与 LDPC 码长不同，不能简单都遮挡“固定 30 个符号”然后声称公平。建议同时记录两种口径：

```text
blockageLengthSymbols
blockageFraction = blockageLengthSymbols / Ntx
```

正式比较优先使用相同遮挡比例。

---

## 6. 突发错误

S5 的突发错误是**无交织基线**；交织方案全面比较属于 S7。老师也明确要求交织结果单独汇总，LDPC 不配置交织。fileciteturn1file11

不建议直接在译码前翻转硬比特，因为：

- CC 软判决和 LDPC 使用 LLR；
- 直接翻转硬比特无法公平反映软信息；
- 会绕过调制和接收链路。

建议使用符号级突发干扰：

```text
连续一段接收符号
→ 加入强脉冲噪声
```

或者擦除式模型：

```text
连续一段LLR置为0
```

两种模型不要混为一个 case。

主线建议采用：

```text
符号级连续强干扰
```

S7 再在同一模型下加入 CC 交织器。

# 五、MATLAB 与 C++ smoke 验证要求

你的 smoke 思路是正确的，但必须注意：

> 仅比较最终 BER/FER 不足以证明链路正确。

每个信道至少比较以下中间层。

## 统一比较层级

```text
L0：payload bits
L1：encoded bits
L2：BPSK复符号
L3：信道状态
L4：无噪声信道输出
L5：标准高斯噪声
L6：加噪接收符号
L7：补偿或均衡输出
L8：硬判决或LLR
L9：decoded payload
L10：bitErrors、frameError、decoder状态
```

## 不要让 MATLAB 与 C++ 各自随机生成

即使 seed 相同：

```text
C++随机数
MATLAB randn
```

通常也不会逐样本一致。

正确做法是：

1. C++ 或 Python 生成固定 payload；
2. 保存固定信道状态；
3. 保存标准复高斯母噪声；
4. C++ 和 MATLAB 读取同一组文件；
5. 比较逐样本结果。

公共工程原先已经采用固定帧池、可复现噪声、SHA256 和跨语言比较机制，本轮应直接复用。fileciteturn0file4

## 每个信道 smoke 至少包含三类样例

```text
A. 无噪声、无损伤
目标：payload完全恢复

B. 有信道损伤、无AWGN
目标：验证信道与接收补偿模块

C. 有信道损伤、有AWGN
目标：验证完整链路通畅和C++/MATLAB一致性
```

# 一、关于 C++ 与 MATLAB smoke：你的补充应当作为硬性 Gate

我赞成，而且应当把“MATLAB 对比”从简单的结果对比，提升为三层验证。

## 第一层：核心公式审计

Codex 不能只看到 C++ 与 MATLAB 输出一致就宣布正确。因为两边如果使用了同一个错误公式，也可能一致。

因此，每个信道 Stage 都必须生成：

```text
formula_audit.md
```

至少逐项记录：

1. 数学模型；
2. C++ 实现函数；
3. MATLAB 实现位置；
4. 参数单位；
5. 公式代入样例；
6. 手工计算结果；
7. 程序输出结果；
8. 误差容差；
9. 审计状态。

例如 AWGN 使用 (E_s/N_0) 时：

[
\gamma_s=10^{(E_s/N_0)_{\mathrm{dB}}/10}
]

实值 BPSK：

[
\sigma^2=\frac{1}{2\gamma_s}
]

如果采用复基带复噪声：

[
n=n_I+jn_Q
]

则应满足：

[
n_I,n_Q\sim\mathcal N\left(0,\frac{N_0}{2}\right)
]

不能在实链路和复链路之间未经说明地复用同一个 `sigma` 含义。

每个公式审计必须至少选取一个固定数值例子。例如：

```text
Es/N0 = 2 dB
gammaS = 10^(2/10)
sigmaSquared = 1 / (2 * gammaS)
```

由 Python 或手工高精度计算独立核验，而不是只比较两个程序。

---

## 第二层：逐元素、逐 bit 比较

你提出“逐 bit 正确”，我建议进一步明确：

### 必须逐 bit 完全一致的内容

```text
payloadBits
tailBits
encoderInputBits
motherCodeBits
puncturedBits
transmittedBits
hardDecisionBits
decodedPayloadBits
bitErrorMask
```

这些字段要求：

```text
mismatchCount = 0
firstMismatchIndex = -1
```

### 浮点数据逐元素比较

```text
BPSK symbols
channel output
noise samples
equalizer output
LLR
path metrics（仅固定短向量审计）
```

浮点数不应要求二进制位完全一致，而应同时检查：

[
|x_{\mathrm{cpp}}-x_{\mathrm{matlab}}|\leq \varepsilon_{\mathrm{abs}}
]

和：

[
\frac{|x_{\mathrm{cpp}}-x_{\mathrm{matlab}}|}
{\max(1,|x_{\mathrm{matlab}}|)}
\leq \varepsilon_{\mathrm{rel}}
]

推荐：

```text
double普通计算：
absTol = 1e-12
relTol = 1e-10

线性方程/MMSE等累计运算：
absTol = 1e-9
relTol = 1e-8
```

具体容差应由 Stage 冻结，不能运行失败后临时放宽。

# 二、MATLAB 与 C++ 必须读取相同公共帧池和噪声池

这一点完全正确，而且现有 Common 工程已经具备良好基础。

当前公共帧池具有：

* 300 bit 确定性 payload；
* 每 1000 帧一个 shard；
* packed-bit 存储；
* LSB-first 位序；
* SHA256 与 overallHash；
* 最大 50000 帧；
* `splitmix64_payload_v2` 生成规则。

公共噪声使用：

* SplitMix64；
* Box–Muller；
* float64；
* frame-major；
* little-endian；
* shard SHA256；
* 同一 frame 在不同 SNR 下复用标准母噪声，只改变缩放。

因此 S5 的 smoke 不应让 MATLAB 使用：

```matlab
randi(...)
randn(...)
awgn(...)
```

直接独立生成随机数据。

正确方式是：

```text
公共payload shard
公共标准高斯噪声文件
公共信道状态文件
             ↓
       C++ 和 MATLAB
       分别读取同一输入
```

每次比较前必须检查：

```text
framePoolId一致
framePoolOverallHash一致
noisePoolId一致
noisePoolOverallHash一致
channelStateHash一致
frameIndex一致
symbolIndex定义一致
```

## 复信道噪声池的补充

当前 Common 的标准噪声主要是一维实高斯。如果 S5 引入复基带，建议不要破坏旧噪声池，而是规定：

```text
zI = motherNoise[2*i]
zQ = motherNoise[2*i+1]
```

或新建版本化复噪声适配规则：

```text
complexNoisePolicyVersion = s5_complex_pair_v1
```

其核心是确定性地将同一公共母噪声映射为 I、Q 两路。

不能由 MATLAB 现场 `randn` 生成 Q 路。

```text
尾比特数 = 6
打孔图样
打孔位序
输入向量行列方向
bit顺序

回溯深度

```

已有项目规划也明确把 trellis、`convenc` 和 `vitdec` 逐帧对比作为卷积码验证任务。

## 需要特别警惕 `vitdec` 的软输入

你当前 C++ 的浮点软判决 Viterbi，不一定能直接与 MATLAB `vitdec(...,'unquant')` 的输入符号约定无缝一致。

必须冻结：

* MATLAB 正软值是偏向 bit 0 还是 bit 1；
* C++ 分支度量使用欧氏距离、相关度量还是 LLR 度量；
* 打孔位置在 MATLAB 中如何表示；
* 尾部译码模式是 `term`、`trunc` 还是 `cont`。

必须先使用 1～3 帧固定短向量，逐路径或至少逐译码 bit 检查，而不能直接跑 100 帧后只比较 FER。

# 五、“信道鲁棒性”究竟是什么

老师所说的“鲁棒性”不是一个像 BER 那样天然唯一的标量。

它的核心含义是：

> 当信道从理想基线发生偏离、出现额外损伤或参数失配时，编码方案维持可靠通信性能的能力。

直观地说：

* 在纯 AWGN 下表现好，只说明基础纠错性能好；
* 在多径、残余频偏、时变多普勒、遮挡和突发干扰下仍然退化较小，才说明鲁棒性好。

## 鲁棒性不能只看某一个信道下的绝对 FER

例如：

```text
方案A在AWGN下 FER=0.001
在多径下 FER=0.02

方案B在AWGN下 FER=0.01
在多径下 FER=0.025
```

多径下 B 的 FER 更差，但：

* A 从 0.001 恶化到 0.02，恶化 20 倍；
* B 从 0.01 恶化到 0.025，恶化 2.5 倍。

因此：

* A 的绝对性能可能仍优；
* B 对多径扰动的相对敏感性更低。

这两个维度都应报告。

---

## 建议把鲁棒性拆成四类指标

### 1. 固定 (E_s/N_0) 下的性能退化

对于信道 (c)：

[
\Delta FER_c(\gamma)
====================

FER_c(\gamma)-FER_{\mathrm{AWGN}}(\gamma)
]

也可计算比值：

[
Q_{FER,c}(\gamma)
=================

\frac{FER_c(\gamma)}
{\max(FER_{\mathrm{AWGN}}(\gamma),\epsilon)}
]

但是高 SNR 下 AWGN FER 为 0 时，比值会不稳定，所以主报告优先使用差值，不要滥用倍率。

---

### 2. 达到相同目标 FER 所需的额外 SNR

这是最直观、最适合写进结论的鲁棒性指标。

例如在：

[
FER_{\mathrm{target}}=10^{-1}
]

或：

[
FER_{\mathrm{target}}=10^{-2}
]

定义信道损失：

[
L_c=
\gamma_c(FER_{\mathrm{target}})
-------------------------------

\gamma_{\mathrm{AWGN}}(FER_{\mathrm{target}})
]

单位为 dB。

含义：

* (L_c) 越小，信道鲁棒性越强；
* 需要多增加 2 dB 才恢复到 AWGN 同一 FER，则该信道损失为 2 dB。

注意只有曲线真实覆盖目标 FER 时才能计算。不得外推。

---

### 3. 可容忍的信道损伤强度

在固定工作 SNR 和 FER 门限下，例如：

```text
FER <= 0.1
```

求最大可容忍：

```text
最大残余CFO
最大归一化多普勒
最大遮挡比例
最大突发长度
最大突发干扰功率
最严重可接受多径profile
```

例如：

[
\varepsilon_{\max}
==================

\max{\varepsilon:FER(\varepsilon)\leq 0.1}
]

这个指标特别符合“鲁棒性”的工程含义。

---

### 4. 时延和稳定性鲁棒性

在恶劣信道下，不只是 FER 变化：

* LDPC 平均迭代次数可能增加；
* NMS 达到最大迭代次数的比例可能升高；
* Viterbi 计算量通常相对固定；
* 译码时延 P95 可能变化；
* 接收机均衡与补偿可能产生额外时延。

因此还应统计：

```text
avgDecodeTimeUs
p95DecodeTimeUs
maxDecodeTimeUs
avgIterations
maxIterationFrameRate
decoderFailureRate
undetectedErrorRate
```

## 最终不建议构造一个任意加权的“综合鲁棒性分数”

我不建议直接定义：

```text
robustnessScore = 0.4×FER + 0.3×delay + ...
```

因为权重没有老师给出的依据，很容易显得主观。

更科学的输出是：

### 鲁棒性向量

```text
信道损失dB
固定SNR的FER退化
最大可容忍损伤强度
P95时延变化
译码失败率
```

### 场景排序

```text
AWGN：
方案排序……

多径：
方案排序……

频偏：
方案排序……

……
```

### 最终推荐矩阵

| 场景 | 可靠性优先 | 低时延优先 | 高吞吐优先 |
| -- | ----- | ----- | ----- |

老师要求的“鲁棒性”最终应落到这种可解释的方案选型，而不是单独画一张名字叫“鲁棒性”的无定义曲线。

# 九、多径信道参数

BCH S2 已经采用过固定三径模型：

```text
raw taps = [1, 0.65, 0.35]
delays = [0, 1, 3] symbol
```

归一化后约为：

```text
[0.804518, 0.522937, 0.281581]
```

总信道能量归一化为 1，并采用已知信道的线性 MMSE 均衡。

这个 profile 可以作为 S5 的首选参考，因为：

* 已在 BCH S2 使用；
* 参数可复现；
* 现有 MMSE 代码可能可复用；
* 时延跨度为 3 个符号，适合短块实验。

## 数学模型

[
r[k]=\sum_{\ell=0}^{L-1}h_\ell x[k-d_\ell]+n[k]
]

## S5 推荐冻结

```text
profileId = fixed_1_065_035_d0_1_3

delaysSymbols = [0, 1, 3]
normalizeChannelEnergy = true
channelVariation = fixed
receiverKnowsChannel = true
equalizer = linear MMSE
convolution = linear
tailHandling = explicitly frozen
```

## 需要重新检查的地方

BCH 使用硬判决，而 CC/LDPC 依赖软信息。多径均衡后，LLR 不能未经考虑直接使用：

[
LLR=\frac{2y}{\sigma^2}
]

因为 MMSE 均衡会改变：

* 有效信号增益；
* 输出噪声方差；
* 不同符号的噪声相关性。

至少需要选择以下一种明确方案：

### 简化方案

均衡后按实测或理论等效增益和方差计算：

[
L_k=
\frac{2g_k\hat x_k}
{\sigma_{\mathrm{eq},k}^{2}}
]

### 工程简化

均衡输出归一化后使用统一等效方差，并在文档中承认忽略噪声相关性。

不能直接无说明地复用 AWGN LLR。

## 建议附加轻度 profile，仅用于 prescan

```text
rawTaps = [1.0, 0.4, 0.2]
delays = [0, 1, 3]
```

正式主线只保留一个 profile，避免规模膨胀。

# 十、载波频偏 CFO 参数

## 数学模型

[
r[k]
====

x[k]\exp\left(j(2\pi\varepsilon k+\phi_0)\right)+n[k]
]

其中：

* (\varepsilon=\Delta f/R_s)：归一化频偏；
* (R_s)：符号率；
* (\phi_0)：初始相位。

## 必须使用复基带

CFO 不能用实数乘法正确表示完整相位旋转。

## 推荐 prescan

```text
normalizedCfo ∈
{0,
 1e-4,
 2e-4,
 5e-4,
 1e-3,
 2e-3,
 5e-3}
```

对于约 600 符号的帧：

[
\Delta\phi_{\mathrm{frame}}
\approx 2\pi\varepsilon(N-1)
]

因此即使 (\varepsilon=10^{-3})，整帧累计相位也可能超过半周，影响很强。

## 正式建议

不要默认直接用极大频偏。应由 prescan 选择一个能够在 SNR 网格中产生可观察分离、但不是全部 FER≈1 的残余频偏，例如候选：

```text
normalizedResidualCfo = 2e-4 或 5e-4
initialPhaseRad = 0
```

正式值必须由 prescan 冻结，不能现在武断固定。

## 接收端条件

主实验建议比较：

```text
A. 理想补偿：验证补偿模块
B. 固定残余CFO：正式编码鲁棒性比较
```

不要以“完全未知且不补偿的大 CFO”作为唯一 formal，因为那主要评价同步器是否失效，不是编码鲁棒性。

# 十一、多普勒信道参数

这里我有一个明确异议：

> BCH S2 现有记录主要覆盖 AWGN、多径、CFO、遮挡、突发错误和交织，没有看到已经完成的独立多普勒正式阶段。现有材料不能支持直接照搬一套已验证的 BCH 多普勒参数。

因此 S5 的多普勒必须作为新模型设计，不能把 CFO 改名为 Doppler。

## 建议模型：时变相位单径

[
r[k]=x[k]e^{j\phi[k]}+n[k]
]

[
\phi[k+1]=\phi[k]+2\pi\varepsilon[k]
]

令频偏随帧内时间线性变化：

[
\varepsilon[k]
==============

\varepsilon_0+
\alpha_D
\left(
\frac{k}{N-1}-\frac12
\right)
]

这样：

* CFO：(\varepsilon[k]) 固定；
* Doppler：(\varepsilon[k]) 随时间变化。

## 推荐 prescan

```text

{0,
 1e-4,
 2e-4,
 5e-4,
 1e-3,
 2e-3}
initialPhase = 0
amplitude = 1
```

## 正式条件

从 prescan 冻结一个中等时变强度，例如：

```text

```

## 不建议第一轮引入

```text

分数时延
多天线
信道估计误差
载波环路
```

否则无法分清：

* 编码性能；
* 信道估计性能；
* 同步性能；
* 均衡性能。

第一轮用单径时变相位，模型清晰、易于 C++/MATLAB 逐元素核验。

# 十三、突发错误/突发干扰参数

BCH S2 的交织实验属于独立线路，而 S5 应只保留**无交织突发基线**。老师明确要求交织作为独立测试项，LDPC 不配置交织。

## 我不建议直接翻转译码输入 bit

因为：

* CC 与 LDPC 均使用软信息；
* 硬 bit 翻转无法公平表达软信息破坏；
* 会绕过信道前端。

## 推荐主模型：连续强高斯干扰

[
r[k]=x[k]+n[k]+b[k]w[k]

其中：

* (b[k]=1)：突发区间；
* (b[k]=0)：非突发区间；
* (w[k]) 为额外强干扰。

## Prescan

```text
burstFraction =
{0, 0.01, 0.02, 0.05, 0.08, 0.10}

burstInterferenceToSignalDb =
{3, 6, 10, 15, 20}
```

不应做完整笛卡尔积。先固定：

```text
burstFraction = 5%
```

扫描强度，再冻结一个有分辨力的强度。

## Formal 候选

```text
burstFraction = 0.05
burstInterferenceToSignalDb = 10 dB（候选）
start = deterministic per-frame random
noWrap = true
oneBurstPerFrame = true
AWGN remains active
noInterleaving = true
```

正式强度必须由 prescan 决定。

## 辅助擦除模型

可以另设：

```text
burstErasure:
连续区间LLR置0
```

但不能和强干扰模型混在同一曲线中。若额度有限，优先做连续强干扰。

LDPC 对 LLR 标度很敏感。

[

必须明确有效增益和有效噪声方差。否则可能错误地得出“LDPC 不鲁棒”，实际是 LLR 标度错误。

# 二、你记得没错：BCH S2 的 CFO 使用的是整帧累计 30°

BCH S2 的 CFO 模型确实是：

* 首符号相位为 (0^\circ)；
* 末符号累计相位为 (30^\circ)；
* 帧内相位线性增长；
* 接收端不做 CFO 估计和补偿；
* 取复接收信号实部后进行零阈值硬判决。

具体模型为：

[
\phi[k]=k\frac{\pi/6}{N-1}
]

[
y[k]=x[k]e^{j\phi[k]}+n[k]
]

S2 只冻结了一个非零 CFO 等级，即整帧累计 (30^\circ)，并增加了 CFO 为 (0^\circ) 时退化为 AWGN 的验证。

## 为什么我之前写成了归一化 CFO？

因为“频偏”常见有两种参数表达方式。

### 表达方式一：归一化频偏

[
\varepsilon=\frac{\Delta f}{R_s}
]

相位为：

[
\phi[k]=2\pi\varepsilon k+\phi_0
]

### 表达方式二：整帧累计相位

直接规定：

[
\phi[0]=0
]

[
\phi[N-1]=\phi_{\mathrm{end}}
]

例如：

[
\phi_{\mathrm{end}}=30^\circ
]

这两者本质上可以互相换算：

[
2\pi\varepsilon(N-1)=\frac{\pi}{6}
]

因此：

[
\varepsilon=\frac{1}{12(N-1)}
]

也就是说，S2 的“整帧累计 30°”不是与归一化 CFO 矛盾，而是另一种参数表达方式。

## 为什么 S5 更适合继续采用 30°累计相位？

因为 S5 要比较的 CC 和 LDPC 码长不同：

```text
CC-R12：约612符号
LDPC-N640：640符号

CC-R23：约459符号
LDPC-N480：480符号
```

如果所有方案使用相同归一化 CFO (\varepsilon)，码长越长，整帧累计相位越大：

[
\phi_{\mathrm{end}}=2\pi\varepsilon(N-1)
]

这会让较长码字天然承受更大的累计旋转。

反过来，如果所有方案统一：

```text
整帧从0°线性旋转到30°
```

那么每一帧都承受相同的总相位漂移，更适合比较“编码结构面对相同整帧同步残差”的能力。

## 我的最终建议

S5 主 CFO Formal 直接继承 S2：

```text
初始相位：0°
末符号累计相位：30°
帧内线性相位增长
不进行CFO估计
不进行CFO补偿
复基带BPSK
AWGN同时存在
```

并保留：

```text
CFO = 0°
```

作为退化到 AWGN 的验证 Gate。

结果文件中同时保存两个等价字段：

```text
endPhaseRotationDeg = 30
normalizedCfo = 1 / (12 * (Ntx - 1))
```

注意：由于 (N_{\mathrm{tx}}) 不同，各方案的 `normalizedCfo` 会不同，但整帧总旋转量相同。这不是错误，而是本次公平性定义。

## 一个需要提前说明的限制

S2 中 BCH 使用硬判决，只取接收复数的实部。S5 中卷积码和 LDPC 使用软信息，因此接收前端必须统一定义：

```text
未补偿CFO
→ 取复信号在原BPSK轴上的投影，即real(y)
→ 根据实轴等效观测计算软信息
```

否则不能一个方案取实部，另一个方案使用复数模长，那会不公平。

# 三、关于跳过 Prescan：可以，但要明确你跳过的是什么

你问：

> Prescan 只是为了确定瀑布区吗？

不完全是。Prescan 原本有三个作用：

1. 定位 waterfall 区域；
2. 判断信道损伤参数是否过弱或过强；
3. 估算正式实验运行时间和错误密度。

你的 Formal 已固定：

```text
Es/N0 = -5～10 dB
步长 = 0.5 dB
```

因此，确实不需要再用 Prescan 定位 SNR 瀑布区。

这一部分我同意跳过。

## 但仍然存在参数强度问题

对于 AWGN、多径、CFO、遮挡，可以直接复用 BCH S2 已经冻结并验证过的参数：

* 多径：固定三径 + MMSE；
* CFO：整帧累计 (30^\circ)；
* 遮挡：固定 10%；
* 突发：复用 S2 的突发设置或按 S5 软信息模型明确改造。

这些不需要再做 Prescan。

但是，多普勒是 S5 新增的。老师原文的 S5 包含多普勒，而 BCH S2 只完成了 AWGN、多径、CFO、短时遮挡和突发错误，没有独立的多普勒正式阶段。

因此多普勒没有历史参数可以直接继承。

## 跳过 Prescan 后的可行办法

在第 1 次提示词生成规划时，直接冻结一个清晰、温和、可解释的多普勒模型；第 2 次 Smoke 使用 1～6 dB 全网格检查该模型。

如果 Smoke 显示：

```text
全部FER≈1
```

或者：

```text
与AWGN完全重合
```

则本阶段状态必须是：

```text
PARTIAL_PASS
```

并只允许修改多普勒参数后重新 Smoke，不能直接进入 Formal。

这不是另开 Prescan，而是将**参数合理性检查并入 Smoke**。

所以我接受：

```text
取消独立prescan阶段
```

但不接受：

```text
无论Smoke结果如何，都直接冻结formal参数
```

正式规则应为：

> 信道参数原则上在规划阶段冻结。Smoke 只验证参数是否可运行和具有基本区分度，不进行系统扫描；只有在参数导致全程饱和、全程无损伤或数值异常时，才允许进行一次有依据的修正并归档旧结果。

# 五、不使用柱状图：赞成

我赞成你取消柱状图。

* BER/FER 随 (E_s/N_0) 的变化；

* 译码时延随 SNR 的变化；

### 性能曲线


纵轴使用对数坐标。

纵轴使用线性坐标。

```text
平均迭代次数 vs Es/N0
最大迭代比例 vs Es/N0
```

例如：

这种表格比柱状图更适合老师快速看结论。

类似“目标 FER 对应的信道损失 dB”本来可以用柱状图展示，但既然你认为没有必要，就直接使用：
