理解了。你说的不是：

* 200 bit 只比较 S200 与 B200；
* 300 bit 只比较 S300、B300、B300-426。

而是对**每一种输入长度都建立完整的四方案横向比较**。

## 200 bit 输入组

固定原始信息长度：

[
K_{\text{payload}}=200\text{ bit}
]

比较四种编码方案：

1. BCH(15,11) 分块编码；
2. 缩短 BCH(255,207)；
3. 缩短 BCH(511,421)；
4. 缩短 BCH(511,385)。

也就是说，后三种母码都需要通过缩短、填充或既定组帧方法承载同一份 **200 bit 信息**。然后在 AWGN、多径、频偏、短时遮挡和突发错误条件下比较，判断哪种编码方案在相应信道下最优。

## 300 bit 输入组

固定原始信息长度：

[
K_{\text{payload}}=300\text{ bit}
]

同样比较四种方案：

1. BCH(15,11) 分块编码；
2. 缩短 BCH(255,207)；
3. 缩短 BCH(511,421)；
4. 缩短 BCH(511,385)。

其中，若母码信息长度不能直接容纳 300 bit，就必须按照项目已经冻结的分块、拼接或组帧规则实现，而不能把该方案直接从 300 bit 组中删除。各方案最终都必须面对相同的 300 bit 原始信息和相同的信道条件。

## 因此，S2的矩阵应当是

| 输入长度    | 编码方案                    | 信道场景               |
| ------- | ----------------------- | ------------------ |
| 200 bit | 分块 BCH(15,11)           | AWGN、多径、频偏、遮挡、突发错误 |

| 200 bit | 缩短 BCH(511,421)         | 同上                 |
| 200 bit | 缩短 BCH(511,385)         | 同上                 |

| 300 bit | 缩短 BCH(255,207)或其合法承载形式 | 同上                 |
| 300 bit | 缩短 BCH(511,421)         | 同上                 |
| 300 bit | 缩短 BCH(511,385)         | 同上                 |

核心比较原则是：

> **一次只固定输入长度和信道场景，然后横向比较四种 BCH 编码方案。**

例如：

* 200 bit、AWGN：四种方案谁最好；
* 200 bit、多径：四种方案谁最好；
* 200 bit、频偏：四种方案谁最好；
* 300 bit、AWGN：四种方案谁最好；
* 300 bit、突发错误：四种方案谁最好。

## 之前实验的主要缺口

你当前的 Case 大致是：

* S200：分块 BCH(15,11)；
* B200：缩短 BCH(255,207)；
* S300：分块 BCH(15,11)；
* B300：缩短 BCH(511,421)；
* B300-426：缩短 BCH(511,385)。

这种设置实际上把不同母码**分配给了不同输入长度**，没有完成老师要求的完整比较矩阵。

例如，200 bit 组缺少：

* 200 bit 输入下的缩短 BCH(511,421)；
* 200 bit 输入下的缩短 BCH(511,385)。

300 bit 组则可能缺少：

* 300 bit 输入下 BCH(255,207)方案的合法承载版本。

因此目前的结果可以证明现有五个 Case 在各信道下的表现，但还不能完整回答：

> 对于200 bit或300 bit输入，在分块编码和三种整块母码方案中，哪一种最优？
