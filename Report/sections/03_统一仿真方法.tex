\section{Common公共仿真基础}

Common 是三类编码共同使用的仿真与审计基础，不参与 BCH 生成多项式计算、卷积码状态转移或 LDPC 校验矩阵迭代。它提供统一类型和接口，固定实值 BPSK、基础 AWGN、硬判决和未量化 LLR 的定义，并通过 Frame Pool、Noise Pool、停止控制、checkpoint、分片合并和结果身份字段约束实验输入与输出。

公共实现解决的是“相同环节如何用同一种方式执行和记录”，不能替代任务级说明。BCH、CC 和 LDPC 的 filler、CRC、tail、puncturing、shortening、量化、译码状态、复杂度字段及扩展信道仍由各任务负责；历史实验是否调用当前 Common 接口，也需要在对应章节逐项复核。

\section{帧结构与长度定义}

$K_{\mathrm{payload}}$ 是原始有效信息长度，也是 BER 分母中每帧贡献的比特数。$K_{\mathrm{codec\ input}}$ 是编码器实际输入，可在 payload 之外包含 filler、CRC 或其他适配位。$N_{\mathrm{encoded}}$ 是 Common \texttt{computeCodeRate} 使用的编码输出长度；具体任务需要说明该字段是否已经完成打孔或速率匹配。$N_{\mathrm{transmitted}}$ 是实际映射到 BPSK 并进入信道的比特数，$K_{\mathrm{recovered}}$ 是去除附加位后的恢复长度。

Shortening 对应的已知位不进入发送序列；punctured 位从母码输出中删除；tail 和 CRC 即使参与译码，也不属于 payload。统计前必须把恢复结果裁剪或映射回 $K_{\mathrm{payload}}$。若恢复长度不同，Common 的 \texttt{countBitErrors} 会拒绝比较，不能用补零或截断掩盖配置错误。

\section{实际码率定义}

现行源码在 \texttt{types.hpp} 的 \texttt{computeCodeRate} 中给出唯一公共码率：
\begin{equation}
  R=\frac{K_{\mathrm{payload}}}{N_{\mathrm{encoded}}}.
  \label{eq:actual-code-rate}
\end{equation}
分子不包含 filler、CRC 或 tail；分块方案的分母使用所有子块最终编码长度之和；打孔后若任务把打孔结果记为 \texttt{encodedLength}，分母使用打孔后长度。母码理论码率不能代替式~\eqref{eq:actual-code-rate}。

$N_{\mathrm{transmitted}}$ 仍需独立保存，用于解释物理发送效率和未发送位。Common-04 基础 \texttt{SummaryRow} 尚未输出该字段，因此正文中的 Common 码率必须按源码写为 payload/encoded，而不能把旧稿中的 payload/transmitted 定义强加给公共函数。若任务结果以 $N_{\mathrm{transmitted}}$ 生成噪声或计算横轴，则在该任务章节登记偏离，并保证 AWGN 和横轴换算使用同一个 $R$。

\section{BPSK离散符号模型}

Common 的 BPSK 调制按逐比特实值映射：
\begin{equation}
  x_i=1-2c_i,qquad c_i\in\{0,1\},\quad x_i\in\{+1,-1\}.
  \label{eq:bpsk-mapping}
\end{equation}
式~\eqref{eq:bpsk-mapping}把比特 0 映射为 $+1$，把比特 1 映射为 $-1$，每个实际编码比特对应一个实值符号。当前 Common 是离散符号级模型，不显式设置采样率、过采样倍数、成形滤波器或载波相位；涉及这些物理层环节的实验不能直接用本节公式覆盖。

\section{Eb/N0驱动的AWGN实现}

\texttt{computeAwgnSigma} 的输入字段为 \texttt{ebN0\_dB}。函数先完成 dB 到线性量的转换：
\begin{equation}
  \gamma_b=10^{(E_b/N_0)_{\mathrm{dB}}/10}.
  \label{eq:ebn0-linear}
\end{equation}
式~\eqref{eq:ebn0-linear}完成 dB 到线性量的转换；随后调用式~\eqref{eq:actual-code-rate}计算实际码率，并返回标准差
\begin{equation}
  \sigma=\sqrt{\frac{1}{2R\gamma_b}},
  \qquad \sigma^2=\frac{1}{2R\gamma_b}.
  \label{eq:awgn-sigma}
\end{equation}
式~\eqref{eq:awgn-sigma}中的 $\sigma$ 进入下列接收模型：
\begin{equation}
  y_i=x_i+\sigma z_i,qquad z_i\sim\mathcal{N}(0,1).
  \label{eq:awgn-channel}
\end{equation}
式~\eqref{eq:awgn-channel}由 \texttt{applyAwgn} 实现；该函数要求符号向量和标准高斯向量等长，并拒绝非有限或非正的 $\sigma$。这里的 $\sigma$ 是标准差而不是方差；Noise Pool 保存的是标准高斯 $z_i$，不是已经按某个 SNR 缩放的噪声。

上述闭式只直接适用于确实调用 Common \texttt{computeAwgnSigma} 和 \texttt{applyAwgn} 的实值 BPSK--AWGN 任务。多径、频偏、遮挡、突发错误或历史 runner 可能采用不同的输入 SNR 和归一化方式，对应章节必须从源码和正式配置重新确认。

\section{Es/N0正式绘图口径}

教师附件要求给出信噪比条件下的 BER、FER 曲线，没有强制横轴为 Eb/N0 或 Es/N0。本报告把正式主图横轴规定为符号信噪比 $E_s/N_0$，同时保留仿真输入 \texttt{ebN0Db}。在一编码比特对应一个 BPSK 符号且使用式~\eqref{eq:actual-code-rate}时，线性关系为
\begin{equation}
  \gamma_s=R\gamma_b.
  \label{eq:es-eb-linear}
\end{equation}
式~\eqref{eq:es-eb-linear}对应的 dB 换算为
\begin{equation}
  (E_s/N_0)_{\mathrm{dB}}
  =(E_b/N_0)_{\mathrm{dB}}+10\log_{10}R.
  \label{eq:es-eb-db}
\end{equation}

式~\eqref{eq:es-eb-db}的换算只增加 \texttt{esN0Db} 展示字段，原始 Eb/N0、噪声样本、$\sigma$、BER、FER、处理帧数和错误计数均保持不变。不得把 \texttt{ebN0Db} 直接改名为 \texttt{esN0Db}，不得用母码率替代实际 $R$，也不得对所有曲线统一减 \SI{3}{dB}。不同码率曲线换算后横坐标不必重合；若需要在同一目标 FER 比较，应限定在各自数据覆盖范围内插值，不能为了对齐网格改变原始点。

\section{硬判决与软信息}

Common 的硬判决在零点明确归入 bit 0：
\begin{equation}
  \hat c_i=
  \begin{cases}
    0, & y_i\ge 0,\\
    1, & y_i<0.
  \end{cases}
  \label{eq:hard-decision}
\end{equation}
式~\eqref{eq:hard-decision}给出硬判决；实值 BPSK--AWGN 的未量化对数似然比为
\begin{equation}
  L_i=\ln\frac{\Pr(c_i=0\mid y_i)}{\Pr(c_i=1\mid y_i)}
     =\frac{2y_i}{\sigma^2}.
  \label{eq:llr}
\end{equation}
由式~\eqref{eq:llr}可知，正 LLR 倾向 bit 0，负 LLR 倾向 bit 1，绝对值表示可靠性。Common 基础接口不执行裁剪、定点量化或饱和；CC 和 LDPC 对软值的位宽、缩放、裁剪和溢出处理必须在任务章节说明。BCH 使用硬判决输入。

\section{BER、FER与译码状态}

公共错误统计只比较原始 payload 和恢复 payload：
\begin{align}
  \mathrm{BER}&=\frac{N_{b,\mathrm{err}}}{N_{b,\mathrm{payload}}},
  \label{eq:ber}\\
  \mathrm{FER}&=\frac{N_{f,\mathrm{err}}}{N_{f,\mathrm{processed}}},
  \label{eq:fer}\\
  S_{\mathrm{payload}}&=\frac{N_{f,\mathrm{correct}}}{N_{f,\mathrm{processed}}}
  =1-\mathrm{FER}.
  \label{eq:payload-success}
\end{align}
式~\eqref{eq:ber}和式~\eqref{eq:fer}分别按 payload 比特与帧计数。Common-04 \texttt{SummaryRow} 中的 \texttt{successRate} 对应式~\eqref{eq:payload-success}，即 payload 无误帧比例，不是译码器声明成功率。

\section{确定性随机噪声与公平比较}

Common 的每个标准高斯样本由完整 NoiseKey 决定：
\begin{equation}
  \mathcal{K}_{\mathrm{noise}}=
  (s_{\mathrm{master}},g_{\mathrm{noise}},f,i,v_{\mathrm{policy}}),
  \label{eq:noise-key}
\end{equation}
式~\eqref{eq:noise-key}的五个分量依次表示主噪声种子、噪声组、帧索引、符号索引和策略版本，对应源码中的 NoiseKey 字段。固定完整键产生相同样本，不依赖随机函数调用顺序。源码使用 SplitMix64 派生均匀字，并用 Box--Muller 变换生成标准高斯值。

\texttt{snrIndex} 和 Eb/N0 不直接进入 NoiseKey。不同 SNR 点通过式~\eqref{eq:awgn-sigma}改变 $\sigma$；是否跨 SNR 复用同一标准高斯底噪，取决于 \texttt{noiseGroupId} 及任务配置。不同 \texttt{frameIndex} 仍生成不同帧噪声，跨 SNR 复用不等于所有帧复用一条噪声。

CC 硬、软 Viterbi 的公平比较应共享 payload、母码输出、打孔结果和 \texttt{receivedSymbols}，只替换译码输入和分支度量。LDPC BP/NMS 应共享 payload、码字、校验矩阵、噪声和 LLR，只替换校验节点更新规则。共享随机样本使结果差异不再同时混入另一组 Monte Carlo 噪声；具体任务是否完全遵守这些条件，仍由对应章节的配置和调用链审计。

\section{帧池和噪声池}

Frame Pool 和 Noise Pool 都支持确定性分片与完整性检查，但文件内容和格式不同，不能互相类推。Frame Pool 保存 payload bits，manifest schema 为 \texttt{common03.frame\_pool\_manifest.v2}；payload 使用 \texttt{splitmix64\_payload\_v2} 生成，按 packed bits、LSB-first 写入。分片必须从 frame 0 开始连续覆盖，每片记录文件名、帧范围、字节数和 SHA-256，overall hash 对稳定 manifest 身份字段和分片 hash 计算。读取器默认复核分片长度与 SHA-256。

Noise Pool 保存未缩放的标准高斯样本，格式为 float64 little-endian，生成算法标识为 \texttt{splitmix64\_box\_muller\_v1}。每个二进制分片含版本化头字段，包括首帧、帧数、每帧符号数、主种子、噪声组和策略版本。manifest 要求连续帧范围、分片 SHA-256 和 overall hash，\texttt{noisePoolId} 取 overall hash 的前16个十六进制字符；读取时同时复核文件 hash 和头字段。

两个 pool 的大型正式文件不进入 Git。报告和 checkpoint 保存 pool ID 或 hash、配置 hash、帧范围和策略版本，使外部存储中的池文件仍能与结果绑定。

\section{仿真停止控制}

Common 正式停止配置为 \texttt{minFrames=5000}、\texttt{targetFrameErrors=200}、\texttt{maxFrames=50000}。\texttt{evaluateStop} 的实际判断顺序如下：

\begin{verbatim}
if processedFrames >= maxFrames:
    MAX_FRAMES
elif processedFrames < minFrames:
    CONTINUE
elif frameErrors >= targetFrameErrors:
    TARGET_FRAME_ERRORS
else:
    CONTINUE
\end{verbatim}

最小帧数防止在错误较多的点过早停止；达到最小帧数后，目标错误帧数提供基本的错误事件数量；最大帧数限制高 SNR 点或低错误率点的计算量。由于每个 SNR 点独立判断，\texttt{processedFrames} 可以不同，不能笼统写成“所有正式点均仿真50000帧”。历史实验或特殊任务若使用其他停止参数，需要在结果表中保存停止配置和 \texttt{stopReason}。

\section{分片与结果合并}

\texttt{mergeSimulationShards} 先按 \texttt{frameStart} 排序，再检查 \texttt{shardIndex} 不重复、每片帧数非零、帧范围连续且没有重叠或空洞。各分片的 experimentId、configHash、frame/noise pool ID、payload/encoded 长度、SNR 索引和 Eb/N0 必须一致；分片统计还要满足 processedFrames 等于 frameCount、totalPayloadBits 等于 frameCount 与 payloadLength 的乘积，并且成功帧与错误帧之和等于分片帧数。

合并时原始计数和时间累计值求和，最大译码时间与最大总时间取各片最大值。BER、FER、成功率和平均时间应在合并后用总计数重新计算，不能直接平均各分片比例。当前基础合并结构未统一覆盖误纠、声明成功、迭代次数或复杂度扩展，具体任务若分片运行，需要为这些字段实现同样的计数一致性和合并规则。

    审计 & stopReason、framePoolId、noisePoolId、configHash & 绑定停止、输入池和配置 \\
    \bottomrule
  \end{tabular}
\end{table}

基础 Schema 尚未统一包含 \texttt{transmittedLength}、miscorrectionRate、decoderDeclaredSuccessRate、置信区间、零错误标志、平均迭代次数、复杂度或交织参数。它们由 BCH、CC、LDPC 或专题任务扩展；扩展结果必须保留基础身份和原始计数，避免只输出无法复核的比例。

\section{零错误点与统计不确定性}

Common-01 定义和 JSON 配置已经冻结 Wilson 95\% 区间、绘图专用 BER/FER 及零错误标志。Common-04 的 C++ 基础汇总结构和指标实现尚未输出这些字段。因此，现阶段把它们作为报告绘图规则和任务扩展要求，不写成公共 runner 已经生成的字段。

原始 CSV 在未观测到错误时保留真实 0。对数坐标图可以使用空点、向下箭头或单独上界标记，不得把 0 静默替换为固定 $10^{-5}$、$10^{-6}$，也不得绘制人为 error floor。若采用零观测事件的三倍法则近似 95\% 上界，则
\begin{align}
  p_{b,\mathrm{upper}}&\approx\frac{3}{N_{b,\mathrm{payload}}},
  \label{eq:zero-ber-upper}\\
  p_{f,\mathrm{upper}}&\approx\frac{3}{N_{f,\mathrm{processed}}}.
  \label{eq:zero-fer-upper}
\end{align}
式~\eqref{eq:zero-ber-upper}和式~\eqref{eq:zero-fer-upper}给出的是统计上界，而不是实测 BER/FER。零观测错误只表示有限样本内未出现事件，不能解释为真实误码概率等于零。

在目标错误率 $p_0$ 上比较候选与参考曲线时，正式 Es/N0 编码增益定义为
\begin{equation}
  G_{\mathrm{coding}}(p_0)=
  \left.\frac{E_s}{N_0}\right|_{\mathrm{reference},p_0}
  -\left.\frac{E_s}{N_0}\right|_{\mathrm{candidate},p_0}.
  \label{eq:coding-gain-esn0}
\end{equation}
式~\eqref{eq:coding-gain-esn0}要求两条曲线都覆盖 $p_0$；只能在局部数据范围内插值，不进行远距离外推。若任一曲线未覆盖目标点，编码增益记为 N/A。

\section{本章小结}

Common 固定了 payload/encoded 码率、实值 BPSK、Eb/N0 驱动的 AWGN、硬判决、LLR、payload BER/FER、确定性随机样本、正式停止控制以及基础 checkpoint、分片和结果身份。正式图按每个点的实际码率把内部 Eb/N0 转换为 Es/N0，原始统计保持不变。任务仍需补充发送长度、附加位、扩展译码状态、量化、专用时延、复杂度和特殊信道；历史结果是否满足公共定义将在第4章以后逐章审计。
